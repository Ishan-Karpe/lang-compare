# Story 1.2: Build-Time Data Transformation Pipeline

## Status

Completed

## Story

**As a** developer,
**I want** a build script that reads `data/language_comparison.md`, applies syntax highlighting, processes custom detail-level comments, and outputs a structured JSON file,
**so that** we have clean, pre-processed data ready for the application to consume at build time.

## Acceptance Criteria

1.  The script uses a robust Markdown parser (e.g., `unified`) to create an AST from `language_comparison.md`.
2.  The script uses a syntax highlighter (e.g., `Shiki`) to transform all code blocks into pre-highlighted HTML.
3.  The script correctly interprets the `<!-- detail:level -->` comments to categorize content.
4.  The script outputs a valid `comparison-data.json` file in the expected structure.
5.  The main `build` command in `package.json` is updated to run this script before `svelte-kit build`.

## Tasks / Subtasks

- [x] Task 1 (AC: 1, 2, 3): Implement the data transformation logic in `scripts/prepare-data.mjs`.
  - [x] Read the `language_comparison.md` file.
  - [x] Use `unified` and `remark` plugins to traverse the Markdown AST.
  - [x] Identify code blocks and use `Shiki` to generate highlighted HTML. [Source: architecure.md#Technology Stack Table]
  - [x] Identify `<!-- detail:level -->` HTML comments and use them to tag the subsequent nodes with the correct detail level.
  - [x] Build a structured in-memory representation of the data.
- [x] Task 2 (AC: 4): Output the structured JSON data.
  - [x] Define the TypeScript types for the final data structure in `src/lib/types/index.ts`. [Source: architecure.md#Data Type Definition]
  - [x] Write the structured data to a `comparison-data.json` file. This file should probably be placed in `src/lib/data/` to be easily accessible by the SvelteKit loader.
- [x] Task 3 (AC: 5): Integrate the script into the build process.
  - [x] Modify the `npm run build` script in `package.json` to execute `node ./scripts/prepare-data.mjs` before the `svelte-kit build` command.

## Dev Notes

### Architecture & Technology

- The script MUST be created at `scripts/prepare-data.mjs`. [Source: architecure.md#Project Structure]
- The script MUST use `unified`/`remark` for parsing and `Shiki` for syntax highlighting. [Source: architecure.md#Technology Stack Table]

### Data Structure

- The output JSON must conform to the `ComparisonRow` and `Snippet` interfaces defined in the architecture. [Source: architecure.md#Data Type Definition]
- The `highlightedCode` property in the `Snippet` interface will contain the raw HTML string generated by Shiki.

### Best Practices & Design Reference

- **Design:** The overall layout and component styling should closely follow the visual reference at `design_iterations/lang-compare-layout_preview.html`.

### Testing

- While no formal unit tests are specified for this story, it is critical to manually validate the output `comparison-data.json` to ensure its structure is correct and all data from the Markdown file is present and correctly processed.
