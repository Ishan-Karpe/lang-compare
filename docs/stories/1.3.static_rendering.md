# Story 1.3: Static Rendering of the Comparison Table

## Status

Approved

## Story

**As a** developer,
**I want** SvelteKit to read the `comparison-data.json` file at build time and use Static Site Generation (SSG) to render the full comparison table into a static `index.html`,
**so that** the application has a near-instantaneous load time.

## Acceptance Criteria

1.  A Svelte component reads the local `comparison-data.json` file during the build process.
2.  The component renders the data into a valid, accessible HTML table structure.
3.  The pre-highlighted HTML for code snippets is rendered correctly using `@html`.
4.  The final `build/index.html` file contains the complete, fully-rendered table.

## Tasks / Subtasks

- [x] Task 1 (AC: 1): Implement the data loader.
  - [x] Create `src/routes/+page.ts`.
  - [x] Import the `comparison-data.json` file.

  - [x] Create `src/lib/components/ComparisonTable.svelte`.

## Dev Notes

### Architecture & Data Flow

- The data MUST be loaded via a `+page.ts` loader to ensure it's available during the static build. [Source: architecure.md#Static Data Loader]
- The application must not fetch or parse the `.md` file on the client. All data comes from the JSON file. [Source: architecure.md#Critical Coding Rules]

### Component Structure

- The main rendering logic should be encapsulated in `ComparisonTable.svelte`.
- Individual code snippets should be rendered in a `CodeCard.svelte` component, which will receive a `Snippet` object as a prop. [Source: architecure.md#Project Structure]

### Best Practices & Design Reference

- **Svelte 5:** Adhere to guidelines in `best-practices/svelte5-best-practices.md` and avoid patterns from `best-practices/svelte5-anti-patterns.md`.
- **DaisyUI 5:** Refer to `best-practices/daisyui5-basics.md` for component usage.
- **Design:** The overall layout and component styling should closely follow the visual reference at `design_iterations/lang-compare-layout_preview.html`.

### Security

- The `@html` directive should ONLY be used for the `highlightedCode` field, which is trusted content generated by `Shiki` at build time. [Source: architecure.md#Critical Coding Rules]
