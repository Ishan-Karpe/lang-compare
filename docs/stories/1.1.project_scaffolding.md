# Story 1.1: Project Scaffolding

## Status

Ready for Review

## Story

**As a** developer,
**I want** to set up a new SvelteKit 5 project with TailwindCSS 4 and DaisyUI 5,
**so that** I have the foundational structure and styling capabilities in place for building the application.

## Acceptance Criteria

1.  A new SvelteKit 5 project is created and configured with `adapter-static`.
2.  TailwindCSS 4 and DaisyUI 5 are successfully integrated.
3.  A basic three-panel layout (sticky header, sticky sidebar, content area) is created for desktop.
4.  The DaisyUI theme controller is implemented, allowing a user to switch between `light`, `dark`, and `black` themes.
5.  The initial structure for a separate build script (e.g., `scripts/prepare-data.mjs`) is created.

## Tasks / Subtasks

- [x] Task 1 (AC: 1): Initialize SvelteKit 5 project.
  - [x] Run `npx sv create ./` to bootstrap the project.
  - [x] Install `@sveltejs/adapter-static`.
  - [x] Configure `svelte.config.js` to use `adapter-static`.
- [x] Task 2 (AC: 2): Integrate TailwindCSS and DaisyUI.
  - [x] Install dependencies: `npm install tailwindcss@latest @tailwindcss/vite@latest daisyui@latest`.
  - [x] Modify `vite.config.js` to add the `tailwindcss()` plugin.
  - [x] Create `src/app.css` and replace its content with `@import "tailwindcss"; @plugin "daisyui";`.
  - [x] Import `../app.css` into `src/routes/+page.svelte`.
- [x] Task 3 (AC: 3): Implement the three-panel layout.
  - [x] Create `src/routes/+page.svelte` as the main layout container.
  - [x] Create `src/lib/components/Header.svelte`.
  - [x] Create `src/lib/components/Sidebar.svelte`.
  - [x] Use DaisyUI's `Drawer` component to structure the responsive layout. [Source: front-end-spec.md#Core Components]
- [x] Task 4 (AC: 4): Implement the theme controller.
  - [x] Create the UI for the theme switcher in `Header.svelte` using a DaisyUI `dropdown`. [Source: front-end-spec.md#Core Components]
  - [x] Create `src/lib/stores/uiStore.ts` to manage the theme state. [Source: architecure.md#State Management]
  - [x] Use `svelte-persisted-store` to persist theme choice. [Source: architecute.md#State Management]
  - [x] Connect the theme switcher UI to the store and apply the theme to the root `<html>` element.
- [x] Task 5 (AC: 5): Create build script structure.
  - [x] Create an empty file at `scripts/prepare-data.mjs`. [Source: architecure.md#Project Structure]

## Dev Notes

### Architecture

- The project will be bootstrapped using the official **SvelteKit 5 starter template**. [Source: architecure.md#Template and Framework Selection]
- The application will be configured to use `adapter-static` for Static Site Generation (SSG). [Source: architecure.md#Template and Framework Selection]

### Tech Stack

- **Framework**: SvelteKit ^2.5.0
- **Styling**: TailwindCSS ^4.0.0
- **UI Library**: DaisyUI ^5.0.0
  [Source: architecure.md#Technology Stack Table]

### Project Structure

- Main page: `src/routes/+page.svelte`
- Header component: `src/lib/components/Header.svelte`
- Sidebar component: `src/lib/components/Sidebar.svelte`
- Build Script: `scripts/prepare-data.mjs`
  [Source: architecure.md#Project Structure]

### State Management

- Global UI state for the theme will be managed in `src/lib/stores/uiStore.ts` using `svelte-persisted-store`. [Source: architecure.md#State Management]

### Best Practices & Design Reference

- **Svelte 5:** Adhere to guidelines in `best-practices/svelte5-best-practices.md` and avoid patterns from `best-practices/svelte5-anti-patterns.md`.
- **DaisyUI 5:** Refer to `best-practices/daisyui5-basics.md` for component usage.
- **Design:** The overall layout and component styling should closely follow the visual reference at `design_iterations/lang-compare-layout_preview.html`.

### Testing

- No specific testing requirements for this story, but the testing framework will be Vitest / Testing Library. [Source: architecure.md#Testing Requirements]
