# Story 1.4: Implement Client-Side Interactivity

## Status

Completed

## Story

**As a** user,
**I want** the Detail-Level Toggle to function on the loaded page,
**so that** I can filter the information displayed in the static table.

## Acceptance Criteria

1.  A UI control for "Simple," "Detailed," and "Expert" is present in the header.
2.  The Svelte component "hydrates" the static HTML with JavaScript.
3.  Toggling the control uses JavaScript to dynamically show or hide the appropriate content (based on classes or attributes applied during the build step) without a page reload.
4.  "Simple" is the default view on first load.

## Dev Notes

### State Management

- The `detailLevel` state (`simple` | `detailed` | `expert`) MUST be managed in `src/lib/stores/uiStore.ts`. [Source: architecure.md#State Management]
- Unlike the theme, this state should not be persisted to localStorage.

### Implementation Strategy

- The filtering should happen entirely on the client-side using JavaScript. There should be no API calls or page reloads.
- The build script from Story 1.2 should have already embedded the `detailLevel` as a data attribute or class on the HTML elements for each code snippet, making it possible for the client-side JS to target them for filtering.

### Best Practices & Design Reference

- **Svelte 5:** Adhere to guidelines in `best-practices/svelte5-best-practices.md` and avoid patterns from `best-practices/svelte5-anti-patterns.md`.
- **DaisyUI 5:** Refer to `best-practices/daisyui5-basics.md` for component usage.
- **Design:** The overall layout and component styling should closely follow the visual reference at `design_iterations/lang-compare-layout_preview.html`.
